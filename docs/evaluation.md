# Synthetic evaluation

Run `npm run evaluate` from the repository root. It compiles and prints a JSON report; use `npm run build` followed by `node dist/src/evaluate.js > evaluation-report.json` for a file containing only JSON. Failed behavioral gates or a measured finalized-event warning above 3000 ms return a nonzero exit status. No environment variable enables live calls in this evaluator.

`fixtures/evaluation-labels.json` supplies independently written, human-reviewable expectations. Each tuple is `[throughSequence, expectedSeverity, requiredEvidenceIds]`; `trigger` identifies the first required high/critical boundary. Required evidence is a minimum set, allowing retained warnings to accumulate additional valid evidence. Every observed prefix has a label, including clear early prefixes. Labels were not reviewed by an independent human. All prefixes and delivery variants of a conversation belong to the same synthetic regression split; there is no train/test split or training.

Coverage includes benign service, OTP safety/training, official-app use, bank claim to OTP disclosure, fake helpdesk remote access, urgent payment redirection, gradual rapport/secrecy escalation, spoken prompt injection, missing delivery sequence, injected provider outage, exact duplicate delivery and repeated OTP requests 20 seconds apart. Labels use only evidence observable by the specified prefix. The public Detector boundary ingests each event and flushes each prefix so provider coalescing cannot hide trigger boundaries. Rapid-turn coalescing is exercised separately in detector tests.

Behavioral gates require the expected severity and required evidence at every prefix; high/critical unsafe warnings by the trigger; zero critical warnings on benign scenarios; no evidence references to unknown or future segments; visible injected faults; retained warning IDs; and unchanged state on exact duplicates. `falseHigh`, `falseCritical` and `missedExpected` count prefixes, not independent conversations; `falseHigh` includes critical alerts where less than high was expected. The repeated-request scenario checks that a second request inside 30 seconds merges evidence without issuing another warning ID. Input-gap degradation is checked independently from provider degradation. The public report API also has a test that injects a false critical provider assessment and confirms evaluation fails. Empty sample sets, incomplete labels and providers labelled Cerebras are refused before assessment.

Latency is measured with the local monotonic clock. Rule-warning samples measure receipt of a finalized JSON event through the first callback exposing each rule warning; useful-warning samples require high/critical severity. Provider-request samples measure the injected provider boundary through response or failure, including the synthetic outages. No prerecorded transcript timestamp is used as elapsed runtime. Provider requests and rule warnings have separate distributions, sample counts, median and nearest-rank p95. A null first-useful-warning latency means that no useful warning occurred (expected for benign calls); unavailable audio-to-warning latency is null. There is no provider-only warning latency estimate because the default mock mirrors the rules. These tiny local timings exclude audio capture, STT, networking and upstream finalization and cannot verify live finalized-phrase-to-warning or audio-to-warning latency.

Calibration is unimplemented and calibrated probability is null. The mock reuses deterministic rules, so this is a regression check against independent literal expectations, not independent model validation. The tiny synthetic dataset does not establish real-world precision/recall, fairness, robustness, calibration or Cerebras quality. Live Cerebras was not called or verified.
